# PeripheralBattery · Windows 11 外设电量工具

在任务栏上横向显示鼠标和键盘的电量或有线供电状态，不用一直开着设备驱动网页。

```text
鼠标  88%  ━━━━━━━━    │    键盘·充电  79%  ━━━━━━━
```

当前版本：**1.3.3**。界面使用 WPF、Win32 和系统托盘，源码没有第三方 NuGet 依赖。

## 功能

- 鼠标、键盘横向并排，18 DIP 大字号百分比，各自保留电量条；低于或等于 20% 时显示橙色。
- CHERRY MX 10.0 RGB 有线款以细线 USB 插头图标表示供电状态，悬停或详情显示“USB 供电”；图标适配明暗主题，不显示虚构电量或电量条。
- 每 30 秒自动刷新，也可手动刷新；两台设备分别查询和处理错误。
- 点击卡片打开详情，查看设备型号、充电状态、数据来源及更新时间。点击窗口外自动收起，卡片继续显示。
- 支持拖动、锁定位置、多屏选择，以及浅色／深色／跟随系统。
- 提供系统托盘入口和可选的登录启动开关，默认不开启登录启动。
- 托盘使用透明底、单色细线电池图标，内部用一条连续色块表示鼠标剩余电量；浅色任务栏使用深色线条，深色任务栏使用浅色线条。低电量变橙色，充电显示闪电，离线为灰色。应用 EXE 使用同一套图形。
- 休眠或断连显示 `—`；详情里的上次结果会标记为“非实时”。
- 日常运行和打开详情均不显示独立的任务栏应用按钮；详情的最小化与关闭按钮收起窗口，单击卡片或托盘可重新打开。重复启动恢复已有详情，菜单“退出”结束后台进程。
- 缓存本次及上次运行状态，记录退出来源、异常堆栈和卡片隐藏原因；日志自动轮转。下次启动能识别未留下退出记录的中断。

任务栏卡片是对齐任务栏的独立覆盖窗口，不会自动给其他任务栏按钮腾出空间。可拖到空白区域，再锁定位置。目标屏全屏或任务栏自动隐藏时，卡片按对应状态隐藏。

## 已验证设备

| 设备 | 已验证连接与标识 |
| --- | --- |
| ROG 月刃2 RGB / KERIS II ORIGIN | ROG OMNI RECEIVER：`0B05:1ACE`，配对 PID `1C0E` |
| CHERRY MX 10.1 | USB 接口：`046A:01EF`，厂商自定义 HID 集合 |
| CHERRY MX 10.0 RGB | USB 有线：`046A:00BB`，只检测连接，无需电池 |

电量通过本地 HID 查询，不要求 Gear Link 网页或 CHERRY Utility 持续运行。MX 10.0 仅枚举设备，不发送 MX 10.1 的电量命令。两款 CHERRY 同时连接时优先显示 MX 10.0。其他 CHERRY 型号、蓝牙直连、其他 ASUS 接收器与 ASUS 有线直连尚未验证或实现。

查询协议与实际兼容范围见 [设备协议说明](docs/protocols.md)。程序只查询状态，不修改设备配置。

## 运行

需要 **Windows 11 x64** 和 **.NET 9 Windows Desktop Runtime x64**。

构建后启动：

```powershell
.\dist\PeripheralBattery.exe
```

保留同目录中的 DLL 和 JSON 文件。单击卡片或托盘打开详情，右键打开设置菜单。托盘电池图标表示鼠标电量，悬停提示同时列出两台设备。

默认位于同屏 AI 用量卡片左侧；没有该卡片时使用任务栏左侧的默认位置。解锁后按住卡片左右拖动，右键“固定位置”可锁定。

## 构建与检查

安装 .NET 9 SDK，在仓库根目录运行：

```powershell
# 61 项协议、设备状态及运行日志检查，不访问硬件。
dotnet run --project tests/ProtocolChecks.csproj -c Release

# 发布到 dist/。更新前请先通过菜单退出正在运行的版本。
.\build.ps1

# 也可发布到单独目录，避免覆盖运行中的程序。
.\build.ps1 -OutputDirectory .\artifacts\publish-check
```

`global.json` 允许使用已安装的 .NET 9 SDK 功能更新版本。发布方式使用系统已安装的 Desktop Runtime，不内嵌运行时。

```text
src/                 应用界面、窗口定位与设备读取器
tests/               协议解析、设备识别、供电状态及运行日志检查
docs/protocols.md    已验证的设备协议
build.ps1            Windows x64 发布入口
dist/                本地运行文件，已排除 Git
artifacts/、work/     本地构建、备份和排查文件，已排除 Git
```

## 设置与诊断

个人设置和运行状态保存在 `%LOCALAPPDATA%\PeripheralBattery`：

| 文件 | 用途 |
| --- | --- |
| `preferences.json` | 主题、显示器、偏移、位置锁定 |
| `status.json` | 两台设备的最新读取状态和错误 |
| `error.log` | 读取失败记录，自动限制大小 |
| `session.json` | 当前／最近一次运行：进程、版本、心跳、卡片状态、退出原因与异常堆栈 |
| `previous-session.json` | 上一次运行快照，启动新实例时保留 |
| `lifecycle.jsonl` | 启动、就绪、详情收起、卡片显隐、系统会话结束、退出及异常事件 |
| `lifecycle.previous.jsonl` | 上一份轮转日志；每份约 256 KiB，最多保留两份 |
| `startup-error.txt` | 主线程未处理异常的备用记录 |

旧版 MouseBattery 的个人设置会在首次启动时导入。更换程序位置后，如已启用登录启动，请在新位置关闭、重新开启一次该选项。

成功状态中的 `Power: null` 和 `IsWired: true` 表示已识别的 USB 供电设备，无电池；读取失败仍由各自的错误字段表示，不会转换为 0%。

运行快照每 30 秒更新心跳。退出原因区分菜单退出、`--exit`、Windows 注销／关机和已捕获的未处理异常；卡片隐藏会记录全屏、用户设置、任务栏或显示器暂时不可用等原因。重复启动与命令行辅助进程不会覆盖主实例的运行快照。

`Phase=exited` 需要退出请求、完成清理、观察到 WPF 退出且退出码为 0；无请求的结束为 `unexpected-exit`，请求后未完成为 `incomplete-exit`，已确认致命异常为 `crashed`。`running` 或 `stopping` 的旧快照没有结束时间时，只能确认记录未完成。清理和迟到回调不能覆盖致命异常原因。

异常记录只保留类型、HResult、有限的代码调用栈和内部异常类型；不记录任意异常消息、Data、URL、源文件路径或服务载荷。升级前的旧日志仍按原样保留在本机；旧格式异常文本不会重新抄入新版会话快照。

强制结束、断电或部分原生崩溃可能来不及写日志；下次启动会记录 `previous-run-incomplete`，保留最后心跳与状态，并明确标为原因未确认；已留下异常结束记录时使用 `previous-run-abnormal`。日志不能追溯旧版本未记录的退出原因，也不会把设备休眠当成程序退出。所有诊断只存本机，不自动上传。

| 参数 | 行为 |
| --- | --- |
| `--details` | 打开或恢复详情 |
| `--menu` | 打开菜单 |
| `--exit` | 正常退出已有实例 |
| `--diagnose` | 本地枚举 HID 并查询设备，生成 `diagnostic.txt` |
| `--inspect-ui` | 界面排查模式，将卡片作为可检查窗口显示 |

诊断文件可能包含本机设备路径，只用于本地排查。个人设置、日志、诊断、安装包及临时分析依赖均已排除 Git。

## 实现说明

- UI 使用 WPF，任务栏定位和层级维护使用 Win32，托盘使用 NotifyIcon。
- 显示器选择保存物理标识；显示设置变化或唤醒后重新定位。
- 详情收起、前台切换和任务栏重排时立即维护卡片层级，避免等待下一次一秒定时更新。
- 鼠标与键盘读取器有独立的成功状态和错误，异步结果回到 UI Dispatcher。
- 不注入或修改 Explorer，不附带厂商程序、驱动、DLL 或固件。
